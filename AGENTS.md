# Working on Zirbel

Zirbel is a local web-game editor, player and host: TypeScript ESM on Node 26 (esbuild, no framework), a native Go host in `host/` (standard library only), the Zirbel box's Wi-Fi setup, controllers and TV console services in Python (`pi/`), and an Electron desktop app in `desktop/`; games with their own netcode play over the spaces kernel (`deps/skalet`). This file is for the people and coding agents who change it; README.md is for the people who use it.

## Check your work

Setup: Node 26.13.1 (`.nvmrc`), pnpm 12 (`packageManager`, which pnpm switches itself to), Go 1.27, git 2.38 or later, and ruff 0.17.6 for the Python checks.

```sh
git submodule update --init && pnpm run deps  # check out and build the submodules (the spaces kernel's binary with Go)
pnpm install --frozen-lockfile
pnpm check                                    # the one gate: must pass before you say a change works
```

The two `link:` dependencies in `package.json` are submodules in `deps/`, pinned to the commits this repository records, and so is the spaces kernel (`deps/skalet`), whose binary `pnpm run deps` builds into `deps/skalet/bin/`; `pnpm run deps` installs and builds them all, and Dependabot proposes updates. Type errors in `harness-activity.ts` or `local-harnesses.ts` usually mean the submodules are not at those commits (`git submodule update --init`, then `pnpm run deps`).

`pnpm check` (`scripts/check.mjs`) runs each of these, every one even after one fails, and lists what passed: `typecheck` (`tsc --noEmit`, strict), `lint` (oxlint `--type-aware` with `.oxlintrc.json`, and knip), `format:check` (Prettier, `.prettierrc.json`; `pnpm format` writes it and ruff's format), `check:files` (the line limit, the Markdown, leftovers, suppressions with their reasons), `check:go` (gofmt, go mod tidy and verify, standard library only, vet, golangci-lint, deadcode, nilaway), `check:py` (`ruff check` and `ruff format --check`, `ruff.toml`) and `test`: the build and the Go host's, the node:test unit and contract tests (both hosts), `go test -race -shuffle=on -count=1 ./...` and the unittest tests of the box's Wi-Fi setup, controllers and TV console services (`pnpm test:pi`, no hardware). `pnpm check --coverage`, as CI runs it, runs `test:coverage` instead: Node at least 80% lines, 70% branches and 75% functions of `packages/`, and Go 76% of statements over its unit and contract tests (`scripts/coverage-go.mjs`).

Add `pnpm check:security` after changing dependencies, workflows, Dockerfiles or anything at the trust boundary: the lockfile (one YAML document, every package from the registry with its hash), hidden characters, licences, secrets in every commit (Betterleaks), zizmor, actionlint and hadolint; `--live` adds OSV-Scanner, Semgrep's registry rules and govulncheck, and CI adds `pnpm audit`.

The repository's other checks: `pnpm contracts` writes `contracts/*.schema.json`, `mcp-tools.json` and `mcp-scene.html` from the Zod schemas (CI runs `pnpm contracts --check`); `pnpm build:host` embeds `dist/web` in the Go host (`host/bin/`); `pnpm test:browser` runs the Playwright e2e tests (first `pnpm exec playwright install chromium`); in `desktop/`, after `pnpm build` here, `pnpm typecheck && pnpm lint && pnpm test`; and Go's fuzz targets, `go test ./host -run '^$' -fuzz '^FuzzName$'` (`.github/workflows/fuzz.yml` runs each for 60 s weekly; plain `go test` runs their seeds).

Tests give the same answer for the same code. They run in a random order: node:test prints `Randomized test order seed: N`, and `node --test --test-randomize --test-random-seed=N --import ./test/setup.ts test/*.test.ts` runs that order again; Go shuffles too, and `go test -shuffle=N` repeats an order `-v` printed. Every test process runs in UTC (`test/setup.ts`, held by `test/determinism.test.ts`). A test that compares the two hosts runs each host as a step of one test, so no test depends on another's order. fast-check properties (`test/properties.test.ts`) run from one fixed seed. No retries, no `.only`, no network beyond loopback, no model calls, no sleeps for timing; CI never writes snapshots.

## Rules

- Validate all external input with the Zod schemas in `packages/sdk/contracts.ts`. Keep the existing size limits (48 MB files, 512 inspector entries).
- Keep the trust boundary. The editor and MCP bind to loopback only, except in box mode (`--box`): there a request from the box's own network needs a paired device's session (an owner's), or an editor's session from a game's edit code, which reaches that one game's routes alone (`box-roles.ts`), `/pair` and `/edit` aside, and `/mcp` answers it only while external MCP access is on, with a project grant. Loopback is the box itself only from the editor's own user or root (`loopback-owner.ts`, `loopback_owner.go`: the connecting socket's uid in `/proc/net/tcp` and `tcp6`, or every loopback request where they can't be read); any other user on the box, such as the TV console's zirbel-tv, comes as from its network. The TV console's user is never the editor's and never in group `input`: the box's gamepads reach its page through the host. `/git/` takes a paired device's or an editor's git token (its game alone), or a project grant while external MCP access is on (its game; pushes with a write grant, to branches that exist). Imports and updates fetch public https repositories only, with none of the person's git settings or credentials, and the host never pushes outside. Game HTML runs in an opaque-origin sandbox with a CSP and never gets editor APIs, credentials or other projects; a net-v2 game also imports its host's `/.skalet/net.js` and `/.skalet/spaces.js` and may reach `/.skalet/spaces`, and joins the space its player page shares with it, never holding a credential. The spaces kernel runs as the host's child on loopback, reached only through the host's proxy: `/.skalet/*` on the player listeners (`x-skalet-listener: player`, the network's audience) and the editor's (`editor`, the owner's: an editor of one game is refused, and its socket answers only this device's own pages), each request with the kernel's token (`x-skalet-proxy`), `x-forwarded-host` and `x-forwarded-for`, and any `x-skalet-*` or forwarding header a client sent dropped; the kernel checks origins, credentials and its own limits. Its socket's address and token stay in the host's process, never in a harness's or a game's environment. A net game's room info is for its space's members alone: the page sends a one-time proof from its own connection (`space.proof()`), which the host checks with the kernel (`space.member`), never the space's id, which is in every link; seats in the space are the kernel's, by its invitation, one-time tickets (a member's own hand-over among them) and members' resume tokens, which Zirbel never reads. LAN guests reach the lobby (offered games, sessions without their codes, starting a session of an offered game, joining one by its code), the rooms they hold a seat or link for, and `/pads` (opening a screen, and a pad of a screen whose code they have, wrong codes counted as the lobby counts them); never the editor, other projects, credentials, or a session's code through the lobby. The host never keeps or logs pad input: it checks a frame's shape, looks only for a button going down (which may take a controller to a screen or a place) and passes it on; a screen's `box` is a socket from loopback, and the local socket of `--pads-socket` is mode 0660, for the controller service's group.
- Box settings' controllers (`/api/box/controllers`) are the owners' alone, never an editor's of one game. The controller service sees every gamepad on the box and BlueZ's pairing; its agent agrees only to the device the owner picked. Pad input is never kept or logged.
- Never write credentials into the project data dir or the repo. Account files go in the per-user account dir; the box's own Wi-Fi password is the setup service's, outside both.
- `host.ts`, `hosting.ts` and everything they import must not import editor code (harnesses, MCP). That keeps `--host-only` small for low-memory hosts.
- Player and editor behaviour lives in both hosts. Change both; `test/editor.contract.test.ts` requires identical normalized responses. Harness chat is Node-only for now. The spaces kernel's child, the `/.skalet/*` proxy with its headers, and a net game's room as a space (its code, tickets, members and end, the lobby's sessions of it) run in both, held together by `test/spaces.contract.test.ts` and `test/spaces-lobby.contract.test.ts`, with the fake kernel and the real one; nothing serves `/mp`, `/zirbel-net.js` or `/zirbel-net/SKILL.md`. The lobby, the TV page and the pad page run in both too, held together by `test/lobby.contract.test.ts`; a game's `controls` from its zirbel.json and on its game page, by `test/editor.contract.test.ts` and `test/game-page.contract.test.ts`; the pads socket (`/pads` and `--pads-socket`), by `test/pads.contract.test.ts`; the MCP server's guides (the same bytes on both) and its file tools, by `test/mcp.contract.test.ts`. Box mode runs in both, held together by `test/box.contract.test.ts`; the Go host's box runs no harnesses. Git as the revision engine (The git store, below) runs in both, held together by `test/git.contract.test.ts` and `test/git-box.contract.test.ts`: the same trees, the same migrated commits, the same refusals. Git is the `git` program (2.38 or later), never a library.
- `game-sdk.ts` runs in every game frame. Keep it free of Zod and use `sdk/bounded.ts`, and within what the frame already needs of a browser (import maps: Chromium 89, Safari 16.4), as TV browsers are: no `structuredClone` or `Object.hasOwn` without a fallback. A game reads every controller through the standard Gamepad API, and a keyboard-only game gets keys from its zirbel.json's `controls`: nothing asks a game to call anything of Zirbel's.
- A gamepad press is no user gesture in every browser: the player page and the pad page unlock audio and full screen on a click, a tap or a key (a TV remote's OK is Enter), never on a gamepad's button alone.
- Pin exact dependency versions, each at least a week old (pnpm-workspace.yaml; check with `npm view <pkg> time`). Run `pnpm check:security --live` after changing them; CI adds `pnpm audit`. The lockfile stays one YAML document (`pmOnFail: ignore`).
- Go is standard library only (`check:go` fails on any module dependency). Tools run through `go run tool@version`.
- The editor shares state through `ws` in `packages/web/state.ts`.
- Keep changes small, typed (`strict`, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`: guards and narrowed types, never `!` or casts in bulk) and covered by a test in `test/`. ### The git store

Every game is a bare git repository, every save a commit, and the editor's listener a git remote. Both hosts implement this; the Node host is the reference (`packages/core/git.ts`, `git-tree.ts`, `history.ts`, `projects.ts`, `migrate.ts`, `git-source.ts`; `packages/server/git-http.ts`, `git-tokens.ts`, `git-hook.ts`), and `test/git.contract.test.ts` and `test/git-box.contract.test.ts` hold the Go host to it: the same trees, migrated commits, refusals and messages.

- **Running git**: the `git` program, 2.38 or later (`merge-tree --write-tree`), with `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=<null device>`, `GIT_TERMINAL_PROMPT=0`, `GIT_NO_REPLACE_OBJECTS=1` and `LC_ALL=C`, so none of the person's or the system's settings apply. Without git the editor exits 1 with `Zirbel needs git 2.38 or later to keep its games' history (found …). Install git and start Zirbel again.` (`--host-only` needs none.)
- **Data directory**: `git/<project>.git/` (SHA-1, `files` refs, `HEAD` → `refs/heads/main`; an optional `zirbel-sha256` cache of `<blob id> <sha256>` lines, rebuilt when missing), `projects/<project>.json` (version 2: `{ version, id, title, template?, notes, attachments, upstream?, imported?, source?: { url, ref? } }`; branches and revisions are git's alone), `proposals/<project>.<proposal>.json`, `assets/<sha256>`, `migrated-projects/<project>.json`, `removed-projects/` and `archived-preview-projects/` (each `.json` with its `.git`), and `git-hooks/pre-receive`, written at every start. A project exists while both its file and its repository do.
- **Refs**: `refs/heads/<branch>`, the branch an `id` (`^[a-z0-9][a-z0-9_-]{0,79}$`; other names are ignored); `refs/zirbel/proposals/<proposal>` (parent: the proposal's base); `refs/zirbel/source` (what an import or update last fetched). `refs/zirbel/` is hidden from clients (`transfer.hideRefs`) and can't be pushed to.
- **A revision's tree** is the game's folder: `index.html` (UTF-8, 1–400,000 characters trimmed), every other game path (`gameFilePath`, listed in `game.files` by SHA-256), the game's own `zirbel.json`, `.zirbel/game.json` (only the fields that differ from their defaults: `maxPlayers` when not 1 and `net` when true, unless `zirbel.json` describes a net game, then `registerObjects`), `.zirbel/scene.json`, `.zirbel/assets.json` (at most 80) with `.zirbel/assets/<sha256>.<png|jpg|webp>`; anything else is kept as it is, never served or changed. JSON is written as `JSON.stringify(value, null, 2) + "\n"`, keys in the schemas' order (`contracts/*.schema.json`), no HTML escaping (Go: `SetEscapeHTML(false)`), shortest round-trip numbers: both hosts write the same bytes.
- **Reading a tree**: refused (and shown without content) with more than 4,000 entries, a symbolic link or submodule anywhere, or more than 48 MB of blobs; a game has at most 1,000 files besides `index.html` and 36 MB with it; a `zirbel.json` whose integer `players.max` is above 1 sets `maxPlayers` (at most 16), `net` and an `adapter` that is one of its `.js`/`.mjs` files, else `.zirbel/game.json` does (above 4 players only with `net`); the scene and assets must be valid, each asset's bytes present with its hash and type. A push, import or update needs a game. The first problem is the one message, in `git-tree.ts`'s words.
- **Writing** over a base changes only `index.html`, the game paths and `.zirbel/`; an unchanged file keeps its blob. Commits are written with `git fast-import` and moved with `git update-ref --stdin`, every move compare-and-swap (Go may use `mktree`/`commit-tree`: only the objects count).
- **Revisions**: a revision's id is its full commit hash. A commit reads as `id, parent (first, or null), restoredFrom (trailer), label (first line, trimmed, at most 120 code points, else Untitled revision), date (committer date, ISO UTC with .000Z), author (name, at most 120 code points, else Unknown), scene, game, assets`, in that order; a game as `html, maxPlayers, net, adapter, registerObjects, files` (files by path). A project's `revisions` are the newest 200 commits reachable from its branches, oldest first, every head among them, only heads in full; `GET /api/projects/:id/revisions/:revision` gives one in full (404 outside its history). Export writes every reachable revision in full; an import replaces the ids and drops `source`. MCP answers carry these as JSON text (`list_revisions` with `author`), so key order is part of the contract.
- **Commits**: the committer is always `Zirbel <zirbel@zirbel.invalid>`; the author is who asked: `Owner <owner@zirbel.invalid>` (loopback, or the box itself), `<label> <device.<id>@zirbel.invalid>` (a paired device), `<name> <editor.<id>@zirbel.invalid>` (an editor of one game), `MCP grant <first 8> <grant.<id>@zirbel.invalid>`, `<harness name> <harness.<processor>@zirbel.invalid>`, and Zirbel itself for a migration (with the revision's own dates). Names lose `<`, `>`, control characters and surrounding space; pushed and imported commits keep their authors. The message is the label on one line, then trailers: `Zirbel-Restored-From: <commit>`, `Zirbel-Revision: <old id>`.
- **How revisions are made**: a new project, folder import, remix or a harness's first game is a root commit on `main`; a proposal is a commit on its ref; apply moves the branch to the proposal's commit (or makes the fork) and deletes the ref in one transaction (409 when its base is no longer the head); a restore commits the target's tree exactly on top of the head, labelled `Restore <label>` (404 unless reachable, 422 with problems); a bundle import writes one commit per revision; an import from a URL keeps the source's commits; an update is a fast-forward or a merge.
- **Git over HTTP**, smart only: `GET /git/<project>.git/info/refs?service=git-upload-pack|git-receive-pack` and `POST …/git-upload-pack|git-receive-pack`, anything else 404, through `git http-backend` as CGI (`GIT_PROJECT_ROOT=<data>/git`, `REMOTE_USER` the author's name) with `http.receivepack=true`, `receive.denyNonFastForwards`, `receive.denyDeletes`, `receive.fsckObjects`, `receive.maxInputSize=134217728`, `receive.autogc=false`, `transfer.hideRefs=refs/zirbel` and `core.hooksPath=<data>/git-hooks` (and `ZIRBEL_GIT_GRANT=1` for a grant's push); a push may take 5 minutes, its headers 10 seconds, and the Node editor's history cache is keyed by the branches' commits, so a push needs no notice. Loopback may fetch and push every game without credentials; a paired device's git token every game; an editor's its own (403 for another); an MCP grant its game, fetching and pushing with a write grant to existing branches only (on a box only while external MCP access is on); anything else on a box's network gets 401 with `WWW-Authenticate: Basic realm="Zirbel", charset="UTF-8"`. Credentials are Basic (any user, the token as password) or Bearer; a request with an `Origin` must come from the editor's own.
- **Git tokens** are derived: `<kind>.<holder id>.<mac>`, kind `o` (paired device) or `e` (editor), mac the unpadded base64url HMAC-SHA256 of `"zirbel-git-token\n" + kind + "\n" + holder id` under the account folder's `box/git-secret` (64 hex digits and a newline, mode 0600); a token works while its device stays paired or its editor's session lasts. A grant's token is `<grant id>.<secret>`. `GET /api/projects/:id/clone` answers `{ url, command, token? }`: `url` is `http://<the host name the request came by>:<port>/git/<id>.git`, and `command` is `git clone <url>` on loopback, `git clone http://zirbel:<token>@…` for a device or an editor.
- **The push check** (`pre-receive`: `node dist/server.mjs git-hook` or `zirbel-host git-hook`) refuses the whole push, in quarantine, unless every update is to `refs/heads/<id>`, no deletion, no new branch from a grant, a fast-forward of an existing branch, and ends at a commit that reads without problems and holds a game (or a scene, for a scene project). The messages are `git-hook.ts`'s, word for word.
- **Import and update**: `POST /api/projects/import-git { url, ref? }` (owners): `url` https with a host and no user, password, query or fragment, at most 2,048 characters; `ref` `^[A-Za-z0-9][A-Za-z0-9._/-]{0,199}$` without `..`, `//`, `@{` or a trailing `/`, `.` or `.lock`, else the remote's default branch. The fetch is `git -c protocol.allow=never -c protocol.https.allow=always -c credential.helper= fetch --no-tags --no-recurse-submodules --quiet <url> +<ref or HEAD>:refs/zirbel/source`, 120 s (504), 192 MB (413), failing as 502; a repository without a game is 422; the title is the URL's last segment without `.git`. `POST /api/projects/:id/update-from-source { branch?, baseRevision }` (owners and the game's editors; 409 for a stale base, 404 without a source) answers `{ updated, project }`: up to date, a fast-forward, or a merge (`merge-tree --write-tree`, the host's commits first, label `Update from source`, checked as a push is); a conflict is 409 naming the files, and nothing moves. `ZIRBEL_GIT_ALLOW_LOCAL=1` (tests only) also takes `file:` and loopback `http:`.
- **Migration** at start, before listening, for each version-1 `projects/<id>.json`: copy it to `migrated-projects/`, build `git/<id>.git.migrating` (one commit per revision in the file's order with its own dates, author Zirbel, `Zirbel-Revision` and mapped `Zirbel-Restored-From` trailers, the branches, each pending proposal on its ref with its base mapped), rename it into place, map the notes' revisions, then write the version-2 file: that write is the commit point, so an interrupted migration runs again.

### The TV page and the box's console

- **The TV page** (`public/tv.html`, `packages/web/tv.ts` and the modules beside it) is served by every player listener at `/tv`, with the lobby page's policy and a `ws:` connection to its own host for the pads socket. It shows the offered games and the sessions as tiles, for a seat named "TV" (a session's code is typed, never listed), and moves with a remote's or keyboard's arrows, OK (Enter) and Back (Escape, Backspace, `GoBack`, `BrowserBack`, webOS's 461, Tizen's 10009) or any gamepad (d-pad or left stick, A or Start, B or Select, a held direction repeating; focus goes to the nearest tile, in line before beside: `tv-focus.ts`).
- It is a screen (`openScreen` in `pads-client.ts`, its resume token in this tab's sessionStorage): places P1 to P8, a QR code for each free place (`/pad/<code>?place=k`), "Press A to take P3" for 30 s, and this device's own gamepads taking a place on their first press. A session goes to its player page with `?screen=tv`, which keeps the same screen, and leaving goes back to `/tv` (`tv-return.ts`); Show on TV goes only to a `/join/` page of this listener. On the LAN listener `/lobby/state` names the lobby's address for other devices (`link`), for the QR codes.
- Its script is built for Chromium 80 and its CSS for what such browsers lay out; without WebGL 2 or import maps it shows the lobby and sends games to a phone. Full screen waits for a key, a click or a tap.
- **The HDMI console** (arm64 only; `pi/image/tv-install.sh` from `pi/tv/` and `pi/image/files/`): `zirbel-tv.service` runs `cage` with the image's Chromium in kiosk mode on `http://127.0.0.1:4174/tv` as the user `zirbel-tv` (groups `video`, `render` and `audio` alone), in a seat session on tty7 (`zirbel-tv.pam`), and is not enabled: the follower (`pi/tv/zirbel_tv.py`, root, `zirbel-tv-follow.service` and `.path`) starts it while a display is connected and the switch is on, stops it otherwise, and leaves it while the editor doesn't answer; it runs at boot, on `/run/zirbel-tv/wake` (the editor's switch) and on a DRM hotplug (`72-zirbel-tv.rules`, which also takes `uaccess` off joysticks). `zirbel-tv.tmpfiles` makes `/run/zirbel-tv` (root's and the editor's group's; it being there is `canShowTv`), `zirbel-tv-hdmi.conf` puts HDMI's sound first, and the editor's unit fixes the player port at 4174 (`ZIRBEL_PLAYER_PORT`). The box report names the displays and the console's and follower's last lines.
- **The switch**, Box settings' "Show the lobby on a TV" (`tv`, both hosts), starts on where a 64-bit box has at least 2 GB of memory and off elsewhere; settings written before it take that default.
- **Loopback** is the box's own only from the editor's user or root: on Linux the uid of the socket in `/proc/net/tcp` or `tcp6` whose local address and port are the request's remote ones and whose remote port is the listener's; elsewhere every loopback request stays the box's own. The setup service runs as root, the harnesses' turns as the editor's user, and the report service doesn't call the editor.

## Don't

- Push, merge, tag, publish or deploy: those are the person's.
- Add Markdown besides README.md, AGENTS.md and `.github/SECURITY.md`; what the product serves is marked `content` in `.gitattributes`.
- Write a file over 500 lines (split it by responsibility), or a suppression without its reason (`// oxlint-disable-next-line <rule> -- <why>`, `@ts-expect-error <why>`, `nosemgrep: <rule> -- <why>`, `//nolint:<linter> // <why>`, `# noqa: <code>  # <why>`).
- Edit generated files: `dist/`, `contracts/*.schema.json`, `contracts/mcp-tools.json`, `contracts/mcp-scene.html`, `host/webfiles/web/`. Change their source and run `pnpm build`, `pnpm contracts` or `pnpm build:host`.
- Use a git library, give git the person's settings or credentials, push outside, or fetch from anything but public https repositories.
- Change one host's player, editor, relay, lobby, MCP, box or git behaviour without the other's.
